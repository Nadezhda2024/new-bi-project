Репозиторий содержит рабочие материалы, Jupyter-блокноты и первые скрипты для исследования API маркетплейса Wildberries и проектирования локального хранилища данных на базе СУБД PostgreSQL.

> **Информация для рекрутеров и проверяющих:**
> Проект находится на этапе R&D (исследования и разработки) и отладки бэкенд-логики. Код не является финальным, структура находится в процессе рефакторинга. Я активно учусь выстраивать архитектуру данных, обрабатывать ограничения внешних API на ходу и использую AI-ментора для разбора сложных инженерных концепций.

## 🎯 Общая концепция проекта
Цель проекта — изучить специфику данных маркетплейса и построить надежное промежуточное хранилище (DWH). Это позволит собирать чистые исторические данные без рисков падения отчетов из-за нестабильности или жестких лимитов прямого подключения BI-систем к API Wildberries.

## 📊 Текущий статус разработки

| Компонент проекта | Текущее состояние |
|---|---|
| Изучение API Wildberries | Проверены ключевые методы, лимиты пагинации и коды ответов |
| Подключение к PostgreSQL | Установлен физический коннект, проверено создание таблиц |
| Загрузка и очистка данных | Разработан прототип транспорта; идет объединение кода |
| Аналитика и дашборд | В планах (визуализация пока не реализована) |

## 🏗 Архитектурные подходы (в процессе реализации)
* **Слой Staging (Текущий фокус):** Написан отказоустойчивый HTTP-транспорт с адаптивным ретраем (обработка ошибок 429 через заголовок X-Ratelimit-Retry с добавлением Jitter ±25%) и логированием в формате JSON. В таблице `raw_financial_reports` создана структура на 42 колонки.
* **Слой Core (В планах):** Проектирование дедупликации данных по уникальному ключу транзакции для защиты от повторных строк при смене статусов заказов.

## 📂 Что исследуется в блокнотах
Основная аналитическая работа и изоляция модулей сейчас происходят в папке `/notebooks`:
* **`research_wb_api.ipynb`** — исследование лимитов API, пагинации (включая курсорную в API Контента) и прототипирование пакетного сбора данных за 5 дней.
* **`test_db_connection.ipynb`** — проверка коннекта к локальной PostgreSQL 18.4 через `psycopg2` и валидация структуры таблицы `raw_financial_reports`.

*Примечание: Файл `main.py` и скрипты в папке `/scripts` на данном этапе выполняют роль изолированных тестов и содержат имитации (mock-заглушки) для проверки общей логики.*
